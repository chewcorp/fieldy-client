# Open questions

Facts about the Fieldy public API that are not yet settled. Each one is a
blank in the design, not a design decision — see the implementation-design
comment on [CCP-629](https://linear.app/chewcorp/issue/CCP-629).

Do not close a row from inference or from a plausible convention. Close it
with evidence: Fieldy's published documentation, or one authenticated request
and its response. Until then, code that depends on the row says so at the call
site and in the handoff.

| # | Question | Decides | Status |
| --- | --- | --- | --- |
| 1 | Auth header name and format | The single line inside `_auth_headers()` | open |
| 2 | Does `api/public/v2` serve an OpenAPI document? | Whether `OPS` is generated by `tools/refresh_ops.py` from the spec, or hand-written from the docs | open |
| 3 | Does the summary arrive on the memory object, or from its own endpoint? | Whether `summaries()` is a projection over one response or a second call | open |

None of these changes the shape of the client. Each fills in one blank.

## Environment blocker

`api.fieldy.ai` is currently refused by the agent sandbox proxy (403 on
CONNECT), and the Fieldy MCP server returned 429 when this work was scoped.
Resolving questions 1 and 3 needs the host allowlisted, or a host with direct
egress. Treat that as a blocker to escalate, not as licence to guess.
